# 我们的小心动 · 情侣打卡小程序

一个只给你和 TA 用的早睡早起打卡小程序：打卡得爱心，爱心在商城换礼物。

**当前进度**：打卡可用（M0–M2，已出体验版），架构骨架 ✅（P1a），
**个人爱心账本 + 登记 + 配对门禁 + 解绑清零 ✅（P1b）**，商城还没开始。

**下一步做什么、先做什么，看 [`待办与开发步骤.md`](待办与开发步骤.md)。**

---

## 一、先跑起来（10 分钟）

### 第 1 步：装微信开发者工具

下载地址：<https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html>
选「稳定版 Windows 64」，一路下一步装完，用微信扫码登录。

> 装工具之前想先看看长什么样？双击 `design/preview.html` 用浏览器打开，
> 那是用同一套样式生成的设计稿（首页 + 记录页），和真机效果 95% 一致。

### 第 2 步：导入项目

打开工具 → 「导入项目」 → 目录选这个文件夹 `D:\情侣软件vibe coding`
→ AppID 那里点「**测试号**」（没有账号也能用）→ 确定。

导入后会自动编译，你就能看到界面了。**这时是「本地预览模式」**：
数据只存在你电脑/手机上，不联网，够你点着玩、改样式、调交互。

> 想立刻看到打卡效果？把电脑系统时间调到 22:00（或者临时改
> `miniprogram/utils/rules.js` 里的 `windows.sleep.start`），点「早睡」卡片就能打卡。

### 第 3 步：注册小程序账号（要真用了才需要）

1. 打开 <https://mp.weixin.qq.com> → 立即注册 → 选「小程序」
2. 主体类型选「个人」，按提示填身份证、手机号（免费）
3. 注册完成后，在「开发 → 开发管理 → 开发设置」里找到 **AppID**
4. 把这个 AppID 填进 `project.config.json` 第一行的 `appid` 字段，替换掉 `touristappid`
5. 回到开发者工具，点右上角「详情 → 基本信息」确认 AppID 已生效

### 第 4 步：开通云开发（两台手机同步数据必须做）

云开发 = 微信自带的数据库 + 云函数 + 存储，**不用自己买服务器、不用域名备案**。

1. 开发者工具顶部点「云开发」按钮 → 开通（有免费额度，两个人用基本花不到钱）
2. 新建一个环境，名字随便（比如 `our-hearts`）
3. 环境建好后复制它的 **环境 ID**（形如 `our-hearts-8g1abc2d3e4f`）
4. 打开 `miniprogram/utils/config.js`，把 `envId: ''` 改成 `envId: '你的环境ID'`
5. 保存 → 工具会自动重新编译，控制台看到 `[数据模式] 云开发` 就成功了

### 第 5 步：建数据库集合

云开发控制台 → 数据库 → 新建集合，一共建 4 个（名字要一模一样）：

| 集合名 | 存什么 |
|---|---|
| `profiles` | 用户信息（昵称、头像、属于哪一对） |
| `couples` | 一段关系（邀请码、状态 pending/active/dissolved） |
| `core_wallets` | **个人爱心钱包**（`_id` 必须是 openid，一人一条） |
| `checkins` | 每一次打卡记录 |
| `heart_logs` | 爱心流水账（每一次加减都留痕） |

> `core_wallets` 是 P1b 新增的**必须建**的集合。少了它，打卡会报"爱心账本写入失败"。

每个集合建好后，点「权限设置」→ 选「**所有用户不可读写**」。
（因为只有云函数能操作数据库，客户端碰不到，最安全。）

### 第 6 步：部署云函数

右键 `cloudfunctions/api` 文件夹 → 「**上传并部署：云端安装依赖**」→ 等它跑完（1~2 分钟）。

### 第 7 步：真机试

工具右上角「预览」→ 手机微信扫码 → 打开小程序。
在手机上点一次打卡，然后去云开发控制台看 `checkins` 集合里有没有多一条记录。

### 第 8 步：让 TA 也能用（体验版）

1. 工具右上角「上传」→ 填个版本号（比如 `1.0.0`）→ 上传
2. 去 <https://mp.weixin.qq.com> → 「管理 → 版本管理」→ 把刚传的版本设为「**体验版**」
3. 「管理 → 成员管理 → 体验成员」里加上 TA 的微信号
4. 把体验版二维码发给 TA，她扫码就能用

> 只有你和 TA 自己用（体验版），**不需要备案、不需要审核**。
> 以后想公开发布给所有人，才需要做小程序备案，那是以后的事。

## 二、两个人怎么配上对

1. **首次进入要登记**：填写用户 ID（互相称呼用，全局唯一）、真实姓名、手机号、生日、性别、自我介绍
2. 你打开小程序，首页会显示一个 6 位邀请码
3. 点「复制」，发给 TA
4. TA 登记后点「输入 TA 的邀请码」→ 粘贴 → 配对成功
5. 之后：各自有**自己的爱心**（互相可见、只能动自己的）、共享打卡日历、同步打卡各 +1

> **没登记 / 没配对时用不了任何功能**，这是故意的。
> **解除绑定**在首页对方卡片下面：会弹两次确认，解绑后两人爱心清零、回到未配对，旧记录封存不删除。

## 三、规则在哪儿改

**规则的唯一来源是 `shared/checkin-rules.js`**（时间工具在 `shared/clock.js`）。
`miniprogram/utils/rules.js` 和 `cloudfunctions/api/modules/checkin/rules.js` 都是它生成的副本，**别手改**。

```js
windows: {
  sleep: { start: '5:00',  end: '23:59' },  // 早睡窗口（你上次改的）
  wake:  { start: '05:30', end: '08:00' }   // 早起窗口
},
hearts: {
  sleep: 1, wake: 1,        // 单项打卡
  fullDay: 1,               // 当天两项都完成
  sync: 1,                  // 两人同一天完成同一项
  streak7: 10, streak30: 50 // 连续里程碑
}
```

改完规则有**三步，少一步都不生效**：

| 步骤 | 做什么 | 为什么 |
|---|---|---|
| 1 | 改 `shared/checkin-rules.js` | 唯一源头 |
| 2 | 双击项目根目录的 **`同步规则.bat`** | 生成 4 份副本（2 端 × 规则/时间）+ 跑两套测试 |
| 3 | 开发者工具里右键 `cloudfunctions/api` → **上传并部署：云端安装依赖** | 云端跑的是"已部署的代码"，不改文件就还是旧规则 |

**第 3 步最容易忘**，症状很迷惑：页面上按钮亮了（客户端是新规则），但一点就提示"还没到时间"（云端还是旧规则）。
现在这种情况首页会弹一条黄色提示告诉你两边不一致，照着做就行。

`同步规则.bat` 里其实就是三条命令，你想手动跑也行：

```powershell
node scripts/sync-rules.mjs   # 生成 4 份副本
node scripts/smoke-test.mjs   # 测打卡规则 + 本地流程，打印当前生效的窗口和分值
node scripts/cloud-test.mjs   # 用假数据库把云函数完整跑一遍（不用部署就能测）
```

> 测试用的是固定的一套规则（不受你的配置影响），所以你改了窗口它照样绿；
> 它同时会检查你的配置有没有写错（格式、开始晚于结束、窗口太短）。

## 五、常见问题

**Q：改了云函数之后，小程序提示「界面还是旧版本」或者「没有这个功能 / 没有这个动作」？**

部署顺序问题。**改了云函数要先部署，再点编译**：

| 谁比较新 | 你会看到 |
|---|---|
| 云函数比界面新 | 「小程序界面还是旧版本，点一下编译」← 友好提示，点编译即可 |
| 界面比云函数新 | 「没有这个功能 / 没有这个动作」← 去右键 `cloudfunctions/api` 重新部署 |

**Q：上传云函数报「请在编辑器云函数根目录（cloudfunctionRoot）选择一个云环境」？**

这是最常见的第一个坑，原因几乎都一样：项目最初是用「测试号」导入的，后来才把 AppID 换成真号。
工具内部的云开发状态还停在“没有 AppID”的时候，所以它认不出云环境。按顺序做：

1. 关掉当前项目（工具左上角「项目 → 关闭当前项目」），甚至直接退出工具
2. 重新「导入项目」→ 目录不变 → AppID 这次选**你自己的** `wx4c9555768b8c728a`（不要再选测试号）
3. 等左下角编译完成
4. 在左侧文件树里 **右键 `cloudfunctions` 文件夹** → 看菜单里的「**当前环境**」→ 选 `cloud1`
   （个别版本没这个菜单项：先点顶部「云开发」按钮进一次控制台，回到编辑器再看）
5. 再 **右键 `cloudfunctions/api`** → 「**上传并部署：云端安装依赖**」→ 等 1~2 分钟
6. 去云开发控制台 → 云函数，确认列表里有 `api`

还不行：工具菜单「设置 → 通用设置 → 清除全部缓存」，重开项目再来一遍。

如果「云端安装依赖」一直失败（网络问题），改用「**上传并部署：所有文件**」——
依赖我已在 `cloudfunctions/api/node_modules` 里装好了（62MB，别再单独装一遍）。

**Q：上传云函数报「指定的FunctionName已存在，请勿重复创建」（ResourceInUse.FunctionName）？**

说明云端已经有一个叫 `api` 的函数了 —— 通常是上一次上传中途失败留下的空壳（先建了函数，装依赖那步挂了）。
二选一：

- **办法 A（推荐，最干脆）**：云开发控制台 → 云函数 → 找到 `api` → 删除 → 回编辑器重新「上传并部署：云端安装依赖」
- **办法 B**：右键 `cloudfunctions` 文件夹（不是 api）→「**同步云函数列表**」→ 工具就知道 `api` 已存在 → 再右键 `api` 上传，这次会走“更新”而不是“新建”

如果两种都还报同样的错，先「清除全部缓存」重开项目。

**Q：记录页显示「服务打了个盹，稍后再试」？**

这是云函数抛异常时的兜底文案（现在已经改成会显示真实原因）。最常见的原因：**没有建 `heart_logs` 集合**。
首页不读这张表，所以首页正常、一进记录页就炸。去「云开发 → 数据库」补建 `heart_logs`，权限选「所有用户不可读写」，
再重新部署云函数即可。记录页现在遇到这种情况不会整个挂掉：日历照常显示，只在上方提示缺哪个集合。

**Q：首页卡片点不动，或者提示"还没到打卡时间"？**
正常。早睡 21:30 才开始，早起 05:30–08:00。改 `rules.js` 的窗口或者调系统时间就能测。

**Q：控制台报 "cloud init error" / "env not found"？**
`utils/config.js` 的 `envId` 没填对，或者云环境还没建好。填完记得重新编译。

**Q：打卡报"服务打了个盹"？**
云函数没部署，或者没建集合。回到第 5、6 步。

**Q：两个人数据不一样？**
检查两件事：`envId` 是否为同一个云环境；TA 是不是真的配对成功了（首页应显示对方头像和「已配对」）。

**Q：想清空测试数据重来？**
云开发控制台 → 数据库 → 进每个集合手动删记录；或者换一个云环境（改 `envId`）。

**Q：能直接上架给所有人用吗？**
可以，但要先做小程序备案 + 提交审核。现在先别管，两个人用得爽最重要。

## 六、下一步（M3 商城）

已经想好的形状：

- 礼物由你俩自己上架：名字、emoji、价格、兑现说明（比如"对方洗碗一次"）
- 爱心是共享池，谁都能兑，扣的是同一个余额
- 兑换后生成一张「券」，状态 待兑现 → 已兑现
- **不做充值、不做真钱支付**：只靠打卡赚爱心，不碰支付合规

想开工的时候跟我说一声「做 M3 商城」，我按现有数据结构往上加。
