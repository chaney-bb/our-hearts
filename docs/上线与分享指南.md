# 上线与分享指南（不备案 / 备案 两条路）

> 你现在的情况：小程序已注册（`wx4c9555768b8c728a`）、云开发已开、代码在本地。
> 这份文档回答两件事：**现在怎么让别人用**、**以后怎么正式上线**。

---

## 一、先看清楚：三条路，能力完全不同

| | 开发版 | **体验版** | 正式版 |
|---|---|---|---|
| 谁能用 | 只有开发者自己（工具里预览） | 你指定的**体验成员**（扫码） | 所有人（搜索 / 扫码 / 分享） |
| 需要备案吗 | ❌ 不需要 | ❌ **不需要** | ✅ **必须备案** |
| 需要审核吗 | ❌ | ❌ | ✅ 提审，一般 1~7 天 |
| 能被搜到吗 | ❌ | ❌ | ✅ |
| 能转发给别人吗 | ❌ | ⚠️ 对方必须是体验成员才行 | ✅ 任何人 |
| 人数上限 | 1 | 十几个人（个人主体未认证大约 15 人，**以后台显示为准**） | 不限 |
| 现在能做什么 | 已具备 | **今天就能做** | 要走完备案 + 审核 |

**结论：想给身边几个人用（包括你对象、朋友）→ 走体验版，今天 10 分钟就能搞定，完全不用备案。**
**想让陌生人也能用 → 必须备案 + 审核，周期通常 1~3 周。**

## 二、路线 A：现在就给别人用（体验版，不备案）

### 第 1 步：上传代码（生成一个"开发版本"）

在微信开发者工具里：

1. 右上角点「**上传**」
2. 版本号填 `1.0.0`，项目备注写「打卡 v2」
3. 等进度条走完（1~2 分钟），提示"上传成功"

> 注意：**上传 ≠ 部署云函数**。云函数是你每次改完要右键「上传并部署」的那个，两回事。
> 上传只是把**小程序界面代码**打包送到微信服务器。

### 第 2 步：设为体验版

1. 打开 <https://mp.weixin.qq.com> → 左侧「管理 → **版本管理**」
2. 找到「开发版本」里刚上传的那条 → 点「**选为体验版**」
3. 页面上会出现一个 **体验版二维码**

### 第 3 步：把对方加成体验成员

1. 左侧「管理 → **成员管理**」
2. 找到「**体验成员**」→ 点「添加」
3. 输入对方的**微信号**或手机号（对方得先关注"微信公众平台"安全助手之类的验证，按提示走）

### 第 4 步：把二维码发给对方

对方用微信扫码 → 打开就是你的小程序（体验版）。

### 体验版的三个注意事项

1. **二维码里的人必须在体验成员名单里**，否则扫码会提示"无权限"。
2. **体验版跟着"上传的那一次代码"走**：你以后改了代码、重新上传、重新设为体验版，对方**重进小程序就是新版**（不用重新扫码，需要清一下小程序缓存或杀掉重进）。
3. **云函数是独立的**：体验版和正式版共用同一个云环境。你在开发工具里改了云函数并部署，体验版立刻生效 —— 所以别在对象正在用的时候乱改规则。

## 三、路线 B：正式上线（备案 → 审核 → 发布）

### 3.1 前置条件（缺一不可）

| 条件 | 说明 | 你现在 |
|---|---|---|
| 小程序已注册 | 个人主体即可 | ✅ |
| 名称已定 | 名称有唯一性，**个人主体一年只能改 2 次**，想清楚再定 | 待确认 |
| 服务类目已选 | 建议「工具 → 效率」或「工具 → 备忘录」，**别选"社交"**（个人主体做不了社交类目） | ⬜ |
| 用户隐私保护指引 | 我们收集了真实姓名/手机号，必须声明 | ⬜ |
| 小程序备案 | 2023-09 起，个人主体也必须备案 | ⬜ |

### 3.2 配「用户隐私保护指引」

路径：管理后台 → 设置 → 服务内容声明 → **用户隐私保护指引**

要勾选/填写的（按本项目实际情况）：

| 收集的信息 | 用途 |
|---|---|
| 手机号 | 情侣之间的身份登记（仅对方可见） |
| 姓名（真实姓名） | 同上 |
| 生日、性别、自我介绍 | 同上 |
| 微信 openid | 识别"你是谁"（系统自动，不用手动声明） |

> 我们的手机号是**用户自己手填**的（个人主体用不了"手机号快速验证"组件），
> 但只要你收集了，就必须在隐私指引里声明。

### 3.3 备案（个人主体）

入口：管理后台 → 设置 → 基本设置 → **小程序备案** → 开始备案

要准备的材料（个人主体）：

1. **主体信息**：姓名、身份证号、手机号、邮箱、证件照片/人脸核验
2. **负责人信息**：一般就是本人
3. **小程序信息**：名称、服务内容（**写"个人生活记录 / 习惯打卡工具"，不要写"社交"**）、服务类目
4. **承诺书**：在线签署

流程和时长：

```
提交 → 平台初审（1~2 个工作日）→ 短信核验（你手机收到验证码，24 小时内要填）
     → 管局审核（各省不同，通常 1~20 个工作日）→ 下发备案号
```

**备案期间**：开发版、体验版照常可用，只是**不能发布**。

> 常见卡点：
> - 服务内容写了"聊天""交友""社交" → 个人主体直接被拒，改描述
> - 主体信息与身份证不一致
> - 短信核验超时（24 小时内没填）

### 3.4 提交审核

备案通过后：

1. 开发者工具「上传」新版本
2. 管理后台「版本管理」→ 开发版本 → 「**提交审核**」
3. 填写：
   - **版本描述**：写清楚这次做了什么
   - **功能页面**：选几个主要页面（首页 / 打卡页 / 我的）
   - **测试账号**：本项目没有账号体系，留空
   - **备注**：⚠️ 见下面 3.5，必须写清楚怎么体验
4. 等待审核（一般 1~7 天，被拒可以改完再提）

### 3.5 ⚠️ 本项目最大的审核风险：审核员配不了对

这是**双人应用上线的通病**，必须提前解决，否则大概率被拒，理由是「功能无法体验」。

原因：审核员用自己的微信打开你的小程序 → 停在「先互相认识一下 / 还没和 TA 配对」→ 点不了打卡 → 判定"功能不完整"。

**三种解法（建议都做）**：

| 解法 | 做法 | 成本 |
|---|---|---|
| **① 审核备注说明** | 备注里写：「本小程序为双人配对使用。请用两个微信号分别扫码、各自登记后，A 生成邀请码发给 B，B 输入后即可体验完整功能。二维码：[贴体验版二维码]」 | 免费，最省事 |
| **② 加"演示模式"** | 未配对时，首页底部放一个「看看它能做什么」入口，进去用假数据展示打卡页（不写库、不能真打卡） | 半天开发 |
| **③ 上线前先自己配好一对** | 你俩先配好、打几天卡，把截图放备注里证明功能可用 | 免费，但审核员自己还是体验不到 |

> 我建议 **① + ②**。①是必须有，②能显著提高通过率。需要的话我给你加演示模式（半天）。

### 3.6 发布

审核通过后 → 管理后台「版本管理」→ 「**发布**」→ 全量发布（一般立即生效，或选定时发布）。

发布后：
- 别人可以**搜索小程序名称**找到
- 可以在「设置 → 基本设置 → 小程序码」生成**正式二维码**，发给任何人
- 可以被**转发到聊天/群**（对方点开即用，不用加成员）

## 六、常见问题

**Q：体验版二维码有有效期吗？**
二维码本身长期有效，但**扫码的人必须在体验成员名单里**。名单最多十几个人。

**Q：我能把体验版直接发到群里让所有人用吗？**
不行。不在体验成员名单里的人扫了会提示无权限。要让所有人用只能走正式发布。

**Q：备案要多久？**
平台初审 1~2 个工作日 + 管局 1~20 个工作日。多数省份 5~10 个工作日。**唯一能加速的办法是材料一次过。**

**Q：能边备案边改代码吗？**
可以。备案审的是"你要做什么"，不是审代码。代码随时可以在体验版上迭代。

**Q：个人主体能做吗？会不会很难通过？**
能，打卡/记录类工具是个人主体最常规的类目。难点只有两个：**服务内容别写"社交"**、**审核员要能体验到功能**。

**Q：改名字有影响吗？**
名称一年只能改 2 次（个人主体），改名后需要重新备案（变更备案）。**定好再动。**

**Q：云开发的免费额度够吗？**
两个人用，远远够。但注意「微信体验版」是试用套餐，控制台会提示到期时间，到期前升级即可。

## 七、我的建议顺序

```
现在（今天）      体验版 + 加体验成员 → 你俩先用 1~2 周
第 1~2 周        收集真实使用问题（规则尺度、扣分体验、日历好不好用）
第 2 周          隐藏占位卡 + 加演示模式 + 配隐私指引 + 选类目
第 3 周          提交备案（等待期继续在体验版迭代，不冲突）
备案通过后        上传 → 提交审核（备注写清双人体验方式）→ 发布
```

**别一上来就备案。** 你现在最需要的是"真用起来发现问题"，而这件事体验版完全够用，还不用等审核。等规则稳定了再花那 1~3 周走流程。
