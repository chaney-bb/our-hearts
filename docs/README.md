## 一、三份主文档（先看这里）

| 文档 | 职责 | 什么时候看 |
|---|---|---|
| [系统架构.md](系统架构.md) | 分层、内核/模块契约、数据、部署架构、关键决策、**功能拓展指南**、反模式与风险 | 想理解整体 / 要加功能 |
| [代码详解.md](代码详解.md) | 小程序基础、逐文件讲解、**打卡模块**、**幂等**、**爱心账本**、**消息通知**、测试调试 | 要读懂代码 / 第一次做小程序 |
| [部署上线与迁移方案.md](部署上线与迁移方案.md) | 本地验收 → 体验版 → 正式上线（备案/审核）→ **App 迁移** | 要发布 / 要迁移 |

**职责边界**：

- 架构文档回答「为什么这样分层、以后往哪加」；
- 代码文档回答「这段代码在干什么、怎么改」；
- 部署文档回答「怎么发出去、怎么迁走」。
- 三者不重复讲同一件事；规则数值只放在 `shared/checkin-rules.js` 和打卡模块的规则文档里。

## 六、文档维护规则

| 规则 | 说明 |
|---|---|
| 单一真相 | 规则数值以 `shared/checkin-rules.js` 为准；文档只做解释 |
| 代码优先 | 文档与代码冲突时，以代码 + 测试为准，并记差异 |
| 改了就跟 | 改代码/规则后，更新对应模块文档 + `项目交接.md` 的「当前状态」 |
| 不重复 | 同一个事实只写在一份文档里，其他文档链接过去 |
| 不写大概 | 接口名、文件路径、数值必须可核对 |
| 图片进 src | 文档配图统一放 `src/images/`，用相对路径引用；体验版二维码等敏感物料只留本机，已写入 `.gitignore` |
| 旧文档不复活 | 需要历史时用 git，不再新建「旧版说明」 |
