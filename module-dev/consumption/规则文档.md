# 消费申请 · 规则文档

> 模块：`consumption` ｜ 状态：🧊 占坑（**规则为提案，尚未实现**）
> 开发细节见 [`开发文档.md`](开发文档.md)。

---

## 一、总则

1. 消费申请是**真钱报备**，不是爱心消费；不改变 `core_wallets`。
2. 单笔金额 **> 50 元**才需要对方审批；≤ 50 元可直接记录（自动通过）。
3. 审批人只能是**对方**；不能自己批自己。
4. 同一笔申请同时只能有一个待处理工单。
5. 已提交的申请**不能修改**；要改就撤回重提。
6. 不做支付、不做报销、不做预算系统。

---

## 二、金额规则

| 项 | 规则 |
|---|---|
| 存储单位 | 整数「分」（`amountCents`） |
| 最小值 | 1 分（> 0） |
| 最大值 | 默认 10,000,000 分（10 万元），可配 |
| 审批门槛 | `> 5000` 分（50 元）才需审批 |
| ≤ 门槛 | 自动通过，`needApproval: false`，不生成工单 |
| 显示 | `¥12.80`（分 / 100，保留两位） |
| 负数/零 | 拒绝，`BAD_AMOUNT` |

## 四、状态机

```
                 ┌──────────────┐
  金额 ≤ 50 ───► │  approved    │  (自动通过，auto: true)
                 └──────────────┘

  金额 > 50
     │
     ▼
  pending ──对方同意──► approved
     │
     ├──对方拒绝──► rejected
     ├──我撤回────► cancelled
     └──超时──────► expired（读时惰性判定）
```

| 状态 | 谁能改 | 说明 |
|---|---|---|
| `pending` | 审批人同意/拒绝；申请人撤回 | 等待处理 |
| `approved` | — | 计入本月花费 |
| `rejected` | — | 不计入 |
| `cancelled` | 申请人 | 不计入 |
| `expired` | 系统 | 超时未处理，不计入 |

**幂等**：
- 同一 `(openid, coupleId, amountCents, purpose, 当天)` 短时间重复提交 → 拒绝（`DUP`）；
- 审批工单用 `core/approvals` 的 `(module,type,refId,from)` 唯一 pending。

## 五、审批规则

| 项 | 规则 |
|---|---|
| 审批人 | `ctx.partner.openid` |
| 审批入口 | 我的 → 消息申请（复用通用工单页） |
| 同意后 | request.status = approved；`reviewedAt`；计入统计 |
| 拒绝后 | request.status = rejected；可附带备注 |
| 非审批人操作 | `FORBIDDEN` |
| 已处理再操作 | `ALREADY_DECIDED` |
| 超时 | 默认 72 小时；读列表时惰性判定为 `expired` |
| 通知 | 站内红点先做；订阅消息以后接 `notify` |

**为什么超时用「读时惰性判定」**：云开发没有常驻定时器，为一个两个人用的功能加定时任务不值得；读列表时顺手把过期的改掉即可。

## 六、统计规则

| 指标 | 口径 |
|---|---|
| 本月已花（我） | 本月 `approved` 且 `openid = 我` 的金额和 |
| 本月已花（TA） | 同上，`openid = TA` |
| 本月合计 | 两者相加 |
| 待审批 | `status = pending` 的笔数 + 金额 |
| 已拒绝/撤回/过期 | 不计入花费 |
| 跨月 | 按 `createdAt` 还是 `reviewedAt`？**建议按 `createdAt`**（花出去的时间），并在文档写明 |

> 统计是**展示**，不写回任何表；每次 `detail` 现算。

## 七、校验规则

| 字段 | 规则 | 错误码 |
|---|---|---|
| `amountCents` | 整数，1 ~ 10,000,000 | `BAD_AMOUNT` |
| `purpose` | 2~50 字，去首尾空格 | `BAD_PURPOSE` |
| `category` | 枚举之一 | `BAD_CATEGORY` |
| 重复提交 | 同人同金额同用途，5 分钟内 | `DUP` |
| 撤回 | 只能撤自己的 `pending` | `FORBIDDEN` / `ALREADY_DECIDED` |

## 八、边界案例

| 场景 | 结果 |
|---|---|
| ¥50.00 | 不需要审批（`>` 才需要） |
| ¥50.01 | 需要审批 |
| 对方 72h 没处理 | 读时变 `expired`，不计入花费 |
| 同意后又想撤销 | 不能撤销；要冲正就再提一笔「退款/冲正」记录 |
| 申请人和审批人是同一人 | 不可能，门禁保证已配对且审批人是对方 |
| 解绑后看旧申请 | 看不到（新 coupleId） |
| 一个月提 100 笔 | 可以，但列表要分页（`limit` + 游标） |
| 金额输入 `12.345` | 前端限制两位；服务端只收整数分 |

## 九、明确不做

| 不做 | 原因 |
|---|---|
| 接微信支付/支付宝 | 个人主体做不了；合规风险 |
| 从爱心扣款 | 爱心是奖励，不是钱 |
| 报销/发票/预算 | 这是记账 App 的活 |
| 公开消费记录 | 隐私 |
| 自动识别账单 | 需要银行/支付接口，另一个量级 |
