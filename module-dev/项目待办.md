### 打卡的已知边界（不是 bug，但要知道）

- 早睡 24:00 关窗、早起次日 12:00 关窗；漏打要等关窗后才结算。
- 结算用**当前规则**，不是「那天生效的规则」（`configAt` 已写好但 settle 没用）。定时器漏跑多天才补算时会有偏差。
- 同步奖默认 0，界面不能开；要开得改 `core_settings` 或默认值。
- 档位数量固定，界面只能改边界/分值，不能增删档位。

## 十二、每次开工的固定 5 步

```powershell
# 1. 先跑基线，必须全绿才动手
node scripts/smoke-test.mjs
node scripts/cloud-test.mjs

# 2. 只做一件事（从上面清单里挑一个编号）
# ...改代码...

# 3. 改完再跑一次，还是全绿
node scripts/smoke-test.mjs
node scripts/cloud-test.mjs

# 4. 真机点一遍（先部署云函数，再编译）
# 5. 提交 + 勾掉清单 + 更新交接文档
git add -A; git commit -m "T33 修余额0时的幂等流水"
```

### 改规则的正确姿势（少一步不生效）

1. 改 `shared/checkin-rules.js`（时间工具改 `shared/clock.js`）
2. 双击 `同步规则.bat`（生成 4 份副本 + 跑测试）
3. 右键 `cloudfunctions/api` → **上传并部署**

### 部署顺序

**改了云函数，先部署再编译。**
云函数比界面新 → 旧界面看到「请编译」提示；
界面比云函数新 → 「没有这个功能/动作」报错。

