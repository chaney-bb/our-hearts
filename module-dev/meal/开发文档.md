## 一、一句话

「今天吃什么」：两个人各点一个想吃的，系统撮合出一个结果，省掉每天的纠结。

本质是**双人协商 + 随机/投票**的小玩法，带一个共享菜品池。

---

## 二、边界

| 做 | 不做 |
|---|---|
| 菜品池（增删、标签） | 接外卖平台/下单/支付 |
| 每天一轮，两人各投一票 | 餐厅推荐、地图、评分 |
| 撮合结果 + 历史 | 复杂投票算法/多轮淘汰 |
| 可选的「避免最近吃过」 | 营养分析、卡路里 |

**不用爱心**：吃什么是快乐，不该有奖惩。
如果以后想「连吃三天外卖扣爱心」，那是事后在别处加 `ctx.penalize`，同样不改内核。

## 五、数据模型（计划）

```
m_meal_dishes
  _id, openid（谁加的）, coupleId,
  name（2~20 字）, emoji, tags[]（如 辣/清淡/快手）,
  weight（1~5，默认 1，用于随机权重）,
  active（true/false，软删除）,
  createdAt

m_meal_rounds
  _id, coupleId, dateKey,
  votes: [{ openid, dishId, at }],
  candidateIds: [dishId...],      // 本轮参与撮合的菜
  resultDishId,                    // 撮合结果
  status: 'voting' | 'decided' | 'cancelled',
  decidedAt, createdAt
```

**为什么用 `dateKey` 而不是自然日**：和打卡一致，用内核日期，避免跨零点两套逻辑。
吃饭不需要 12:00 切分，直接用 `ctx.dateKey`（自然日）即可。

**索引建议**：`(coupleId, dateKey)` 唯一（一天一轮）；`(coupleId, active)`。

## 六、接口（计划）

| action | 入参 | 返回 | 说明 |
|---|---|---|---|
| `meal.summary` | — | `{ status, resultText, sub }` | 首页摘要：今天吃了啥/等投票 |
| `meal.detail` | — | `{ dishes, round, history, config }` | 菜品池 + 今日轮 + 历史 |
| `meal.act` | `{ dishId }` | `{ round }` | 投票（每人每天一票，可改） |
| `meal.dishAdd` | `{ name, emoji, tags, weight }` | `{ dish }` | 加菜 |
| `meal.dishRemove` | `{ id }` | `{ ok }` | 软删除（`active=false`） |
| `meal.reroll` | — | `{ round }` | 双方同意后重来（可选） |

> `act` 是「投票」，不是「打卡」；不要复用 checkin 的语义。

## 七、撮合规则（建议 MVP）

```
1. 今天还没有 round → 创建 round（status=voting），候选 = 所有 active 菜
2. 我投票 → 写入 votes（同一人只保留最新一票）
3. 两人都投了：
   a. 两人选同一道 → result = 那道，status=decided
   b. 两人选不同 → 随机二选一（用 round 的 _id/时间做种子），status=decided
   c. 一方没投 → 保持 voting
4. 结果写入 resultDishId + decidedAt，双方看到同一个结果
5. 第二天 00:00 后，新的 dateKey → 新 round
```

**为什么「不同就随机」**：
- 投票/多轮淘汰对两个人来说太重；
- 随机有「听天由命」的乐趣，也避免一方总让步；
- 结果落库，双方看到的一致，不会各随机各的。

**备选**：
- 轮流制（单日我决定、双日 TA 决定）——更公平，但少了随机感；
- 加权随机（按 `weight`）——适合「有些菜更想吃」；
- 两人都选同一道才开饭，否则重投——会卡住。

> 先做「同则定，不同则随机」，跑顺了再谈。

### 第 4 步 · 集合

建 `m_meal_dishes`、`m_meal_rounds`，权限「所有用户不可读写」。

### 第 5 步 · 前端接口层 + 页面 + 双注册

照 checkin 的结构抄；`enabled: true`。

### 第 6 步 · 测试

- 两人选同一道 → 结果就是它；
- 两人选不同 → 结果是两者之一，且两次读一致；
- 一人没投 → 保持 voting；
- 同一人改票 → 只保留最新；
- 一天只能一轮（dateKey 唯一）；
- 删除菜后，本轮候选不受影响（快照）。

## 十、风险与待拍板

| 问题 | 建议 |
|---|---|
| 撮合方式 | 同则定，不同随机；先不做复杂投票 |
| 菜品池共享还是各自 | 共享；谁都能加，删只能删自己的 |
| 要不要「避免最近吃过」 | 可选，默认关；开了降低重复 |
| 要不要通知对方投票 | 先不做；以后 `notify` |
| 历史保留多久 | 90 天，列表分页 |
| 同一天能不能重来 | 双方都同意才 `reroll`，否则会反复 |
