# 消息通知 · 规则文档

> 服务：`notify`（内核通道） ｜ 状态：⬜ 规划（**尚未实现**）
> 开发细节见 [`开发文档.md`](开发文档.md)。

---

## 一、总则

1. 通知是**通道**，不是业务；模板和文案归各模块。
2. 用户不授权就不发；站内红点永远保留。
3. 同一件事只发一次；同一类每天最多一条。
4. 通知失败**不能影响主业务**（打卡、审批该成功还是成功）。
5. 不做营销、不做诱导、不买第三方推送。

---

## 二、什么时候发

| 场景 | 发 | 理由 |
|---|---|---|
| 有新工单待对方处理 | ✅ | 对方不打开就不知道 |
| 工单被同意/拒绝 | ✅ | 申请人需要知道结果 |
| 月度全勤达成 | ✅ | 正向反馈 |
| 21:30 还没打卡 | ⚠️ 受限 | 一次性授权只能发一条，不能天天发 |
| 对方打卡了 | ❌ | 骚扰 |
| 对方没打卡 | ❌ | 制造监督压力 |
| 商城有新礼物 | ❌ | 营销 |
| 连续打卡里程碑 | ⚠️ | 可做，但要频控 |

---

## 三、频控

| 规则 | 值 |
|---|---|
| 同一 `idemKey` | 只发 1 次 |
| 同一用户同一模板 | 每天最多 1 条 |
| 同一用户所有模板 | 每天最多 3 条 |
| 静默时段 | 22:30 – 08:00 不发（打卡提醒除外，21:30 前） |
| 新用户首日 | 最多 1 条 |

**幂等键格式**：`notify:<业务>:<业务主键>[:<用户>]`
例子：
- `notify:approval:<ticketId>`
- `notify:approval_result:<ticketId>`
- `notify:monthly:<YYYY-MM>:<openid>`
- `notify:remind:sleep:<dateKey>:<openid>`

---

## 四、模板字段规则

| 类型 | 限制 | 注意 |
|---|---|---|
| `thing` | 通常 ≤20 字 | 超长会被微信拒绝；服务端截断 |
| `time` | `YYYY-MM-DD HH:mm` 等固定格式 | 不要传时间戳 |
| `number` | 数字 | 不要带单位 |
| `phrase` | 枚举短语 | 按模板可选值 |
| `character_string` | 字母数字 | 订单号等 |

**文案原则**：
- 一句话说清「发生了什么 + 要你做什么」；
- 不夸张、不诱导、不制造焦虑；
- 不出现「快来看」「最后一天」这类营销词。

---

## 五、用户授权规则

| 项 | 规则 |
|---|---|
| 何时请求 | 用户主动点「提醒我」/「接收通知」时 |
| 能否自动弹 | ❌ 不能（微信会拒绝，体验也差） |
| 拒绝后 | 不再反复弹；站内红点继续工作 |
| 授权记录 | 可记「用户某时同意过」，但**额度由微信管理**，服务端无法保证还能发 |
| 一次性 | 同意一次 = 一条；发完需重新授权 |

---

## 六、发送结果

| 结果 | 记录 | 业务影响 |
|---|---|---|
| `sent` | `core_notify_logs` status=sent | 无 |
| `skipped`（重复/频控） | 不写或写 skipped | 无 |
| `failed`（模板/额度/网络） | status=failed + errCode | **无**，不阻塞 |
| 用户拒收 | 微信返回错误 | 无，降级到站内 |

---

## 七、边界案例

| 场景 | 结果 |
|---|---|
| 同一张工单创建两次 | 第二次 `TICKET_EXISTS`，不会发两条 |
| 通知发了但用户没看到 | 站内红点仍在 |
| 用户换了手机 | 授权跟着微信账号，不跟着设备 |
| 模板被下架 | 发送失败，记录 failed；换模板 |
| 体验版 | `miniprogramState: 'trial'`，否则点不开 |
| 正式版 | `formal` |
| 开发版 | `developer` |
| 深夜有新工单 | 静默时段不发，次日 8 点后补发？**建议不补**，站内红点即可，避免堆积 |

---

## 八、明确不做

- 营销推送、活动通知；
- 给未授权用户发；
- 第三方推送平台（个人项目没必要）；
- 用通知催打卡/催付款（可以提醒一次，不能反复）；
- 把通知当唯一入口（必须有站内兜底）。

## 九、待拍板

| # | 问题 | 建议 |
|---|---|---|
| 1 | 先做哪个场景 | 审批提醒（低频高价值） |
| 2 | 每日打卡提醒怎么做 | 小程序端只能「授权一次发一条」；要每天提醒需换方案（公众号/App） |
| 3 | 静默时段 | 22:30–08:00 |
| 4 | 失败要不要重试 | 不重试；记录日志，站内兜底 |
| 5 | 要不要记「用户同意过」 | 可记，但不能当发送凭据 |
