# 礼物商城 · 规则文档

> 模块：`shop` ｜ 状态：⬜ 规划（**规则为设计稿，尚未实现**）
> 开发细节见 [`开发文档.md`](开发文档.md)。

---

## 一、总则

1. 礼物由**你们自己上架**：名字、emoji、价格、兑现说明。
2. 爱心是**个人财产**：A 的爱心只属于 A，B 的只属于 B。
3. 支持**独自购买**（自己付全部）和**合资购买**（各付一半、各点一下）。
4. 兑换后生成一张**券**，状态：待付款 → 待兑现 → 已兑现。
5. **不做充值、不做真钱支付、不做实物配送。**

---

## 二、礼物规则

| 字段 | 规则 |
|---|---|
| 名称 | 2~20 字 |
| emoji | 1 个 |
| 价格 | 1~999 爱心（整数） |
| 兑现说明 | 2~50 字，如「对方洗碗一次」 |
| 状态 | 上架 / 下架（软删除） |
| 谁能上架 | 双方都可以 |
| 谁能下架 | 上架者自己（或双方？建议上架者） |
| 改名/改价 | 建议下架后重上；已产生的订单存快照，不受影响 |

---

## 三、购买模式

### 3.1 独自购买

```
A 点「兑换」→ 创建订单（payerMode=single，payers=[{A, price, paidAt:null}]）
A 点「支付」→ 扣 A 的爱心 → paidAt 打上 → 订单 paid → 生成券
```

- 一次只涉及一个人的钱包；
- 余额不足 → 拒绝，订单保持 pending；
- 付完即可由对方兑现。

### 3.2 合资购买（各付一半）

```
A 点「合资兑换」→ 创建订单（payerMode=split，payers=[{A, half}, {B, half}]）
A 点「我出 5 分」→ 只扣 A → A.paidAt 打上 → 订单仍 pending
B 点「我出 5 分」→ 只扣 B → B.paidAt 打上 → 两人都付 → 订单 paid → 生成券
```

- **每一笔都只涉及一个人**，不需要跨用户原子事务；
- 价格是奇数怎么办？建议**向上取整给发起方**，或只允许偶数价；先允许奇数，规则写明「A 付 ceil(price/2)，B 付 floor(price/2)」；
- 一方付了、另一方不付 → 订单停在 pending，24 小时后自动取消 + 退款。

## 四、订单状态机

```
pending ──双方/单方付完──► paid ──对方确认兑现──► fulfilled
   │
   ├── 任一方取消 ──► cancelled（已付原路退回）
   └── 超过 24h 还有人没付 ──► cancelled（自动，已付原路退回）
```

| 状态 | 含义 | 可执行动作 |
|---|---|---|
| `pending` | 等付款 | 付款、取消、超时自动取消 |
| `paid` | 已付清，等兑现 | 兑现（建议不可取消） |
| `fulfilled` | 已兑现 | 只读 |
| `cancelled` | 已取消/过期 | 只读 |

**规则**：
- 只有 `paid` 才能兑现；
- 只有 `pending` 能取消；
- 取消必须退款（反向流水）；
- 兑现后不能退款。

## 五、扣款与退款

| 项 | 规则 |
|---|---|
| 扣款 | `hearts.spend(openid, amount, { module:'shop', refId:orderId, idemKey:'order:<id>:<openid>' })` |
| 余额不足 | `INSUFFICIENT`，订单不变 |
| 幂等 | 同一个订单同一个人最多扣一次 |
| 退款 | 反向流水 `delta=+amount`，`idemKey='refund:<id>:<openid>'`；不删原流水 |
| 部分退款 | 只退已付的人 |
| 退款后订单 | `cancelled`，保留 `payers[].paidAt` 和退款记录 |
| 余额下限 | 0；退款只能加，不会负 |

**禁止**：
- 直接改 `core_wallets.balance`；
- 删 `heart_logs`；
- 用「赠送」把爱心转给对方（会变成刷分）。

## 六、兑现规则

| 项 | 规则 |
|---|---|
| 谁兑现 | `fulfillerOpenid`（建议：对方 / 礼物提供方） |
| 怎么确认 | 对方点「已兑现」→ `fulfilled` |
| 兑现后 | 不可撤销 |
| 对方不兑现 | 目前只能提醒（以后 notify）；不做自动退款 |
| 合资的券谁兑现 | **待拍板**：建议由「非发起人」或礼物上架者确认 |

> 这是最容易扯皮的地方：爱心已经花了，服务没兑现。
> 产品上建议：券长期有效 + 提醒；不要做「自动退款」，否则会有人白嫖。

---

## 七、过期与取消

| 场景 | 处理 |
|---|---|
| 合资一方 24h 不付 | 读订单列表时判定过期 → 取消 + 退已付 |
| 主动取消 pending | 允许；退已付 |
| 已 paid 想取消 | 不允许；需要双方线下协商 |
| 已 fulfilled | 不允许 |
| 过期时间可配 | `expireHours: 24` |

**为什么用读时惰性判定**：云开发没有常驻定时器；两个人用，读列表时顺手处理足够。

## 八、校验与错误

| 场景 | 错误码 |
|---|---|
| 礼物不存在/已下架 | `NOT_FOUND` |
| 价格越界 | `BAD_PRICE` |
| 余额不足 | `INSUFFICIENT` |
| 重复支付 | 幂等跳过，返回已付 |
| 不是付款人却支付 | `FORBIDDEN` |
| 未付清就兑现 | `NOT_PAID` |
| 已兑现再操作 | `ALREADY_DONE` |
| 取消已 paid | `CANNOT_CANCEL` |
| 合资关闭 | `SPLIT_DISABLED` |

## 九、边界案例

| 场景 | 结果 |
|---|---|
| 价格 11，两人合资 | A 6、B 5（或按约定）；写进订单快照 |
| A 付了，B 余额不足 | B 付不了；订单 pending；24h 后取消退 A |
| A 付了又取消 | 退 A；订单 cancelled |
| 两人同时点支付 | 幂等键防重复；各自只扣一次 |
| 礼物下架后看旧订单 | 订单有快照，正常显示 |
| 解绑后看旧订单 | 看不到（新 coupleId） |
| 兑现后解绑 | 旧订单封存，不影响余额 |
| 余额刚好等于价格 | 可以买，余额变 0 |

## 十、明确不做

| 不做 | 原因 |
|---|---|
| 充值/买爱心 | 虚拟货币 + 支付合规；破坏「靠坚持获得」 |
| 真钱支付 | 个人主体不支持；审核红线 |
| 实物配送 | 另一个量级 |
| 抽奖/盲盒/概率 | 合规风险 |
| 爱心转账 | 会被用来刷分 |
| 自动退款（已兑现） | 会被白嫖 |
