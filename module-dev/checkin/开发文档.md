## 一、一句话

按服务器时间判定早睡/早起窗口，按打卡时刻分档发爱心；漏打扣分，可申诉；月度全勤额外奖励；规则可配、改规则要对方同意。

---

## 二、用户流程

```
首页宫格「早睡早起」→ 打卡页
  ├─ 顶部：连续全勤天数 + 云端时间
  ├─ 本月全勤：18 / 22（达标显示 🎉）
  ├─ 漏卡卡片：🌙 早睡漏打 · 2026-10-24 [说明一下]
  ├─ 这一晚的打卡：早睡 21:30–24:00 [打卡] / 已完成
  ├─ 当月日历：粉=我，蓝=TA；实心/半透/细线
  └─ 右上角 ⋯：查看规则明细 / 修改打卡规则（提交审批）
```

首次进入前有门禁：没登记 → 登记页；没配对 → 首页邀请码卡片。

## 四、数据模型 `checkins`

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 自动 |
| `openid` | string | 谁打的 |
| `coupleId` | string | 哪段关系（**所有查询必须带**） |
| `date` | string | 打卡日 `YYYY-MM-DD`（不是自然日） |
| `type` | string | `sleep` / `wake` |
| `at` | number | 真实打卡时间戳（毫秒） |
| `hearts` | number \| null | 这一项得分；0 也记 |
| `source` | string | `normal`；补签以后用 `makeup` |

**0 分档也要写记录**：日历要显示「打了但没分」，全勤统计只看有没有打卡。

**索引建议**：`(openid, coupleId, date, type)`。云开发控制台可建组合索引；量小不建也能跑。

## 五、接口

| action | 入参 | 返回 | 错误 |
|---|---|---|---|
| `checkin.summary` | — | `{ todayDone, todayTotal, streak, sub }` | 门禁 |
| `checkin.detail` | — | `{ streak, today, recent, month, calendar, misses, config }` | 门禁 |
| `checkin.act` | `{ type }` | `{ reward:{delta,reasons}, detail, streak }` | `BAD_TYPE` `NOT_YET` `CLOSED` `DUP` |
| `checkin.history` | `{ month? }` | `{ month, days, stats, logs, hearts }` | 门禁（当前 UI 未调用） |
| `checkin.settle` | — | `{ penalized:[{day,type,amount}] }` | 内部；`scheduler` 调用；**目前客户端也能调**（幂等，建议加 guard，T71） |
| `checkin.appeal` | `{ dayKey, type, reason }` | `{ ticketId, status }` | `BAD_TYPE` `BAD_DAY` `NOT_PAIRED` `NO_APPEAL` `NOT_CLOSED` `ALREADY_DONE` `EXPIRED` `NEED_REASON` `TICKET_EXISTS` |
| `checkin.proposeConfig` | `{ config }` | `{ ticketId, status, summary }` | `NOT_PAIRED` `EMPTY` `INVALID` `TICKET_EXISTS` |

> `summary` / `detail` / `act` 都会顺手做一次惰性结算。
> `settle.run` 是系统入口，只允许定时触发器或测试 `force`。

## 六、核心流程

### 6.1 打卡 `act`（12 步）

```
1. 校验 type ∈ {sleep, wake}
2. windowState(type, ctx.now, cfg) → upcoming/open/expired
3. dayKey = sleepDayKey(ctx.now, cfg)
4. 查 (openid, coupleId, dayKey, type) 是否已有 → DUP
5. heartsAt(type, ctx.now, cfg) → 档位分（0 也要）
6. store.add(dayKey, type, base) 先写业务记录
7. base > 0 → ctx.award(base, '早睡打卡', { refId: dayKey })
8. syncBonus > 0 且对方也打了 → ctx.award(syncBonus)
9. 当天两项齐 → 查本月全勤天数 → 达门槛 → ctx.award(monthly.bonus, idemKey=monthly:<月>)
10. 重新拉 fullDayKeys → calcStreak
11. return { reward, detail, streak }
12. detail 内部再 settle 一次（把其他漏打补扣）
```

代码：`cloudfunctions/api/modules/checkin/index.js:184`。

### 6.2 结算 `settle`

```
for day in 最近 4 个打卡日:
  if day < 配对日: skip
  for type in [sleep, wake]:
    if 没配置 missPenalty: skip
    if !windowClosed(day, type, cfg, now): skip
    if 已有打卡记录: skip
    ctx.penalize(missPenalty, '漏打', { idemKey: 'miss:<type>:<day>' })
```

- 早睡：D+1 00:00 之后才算缺卡；
- 早起：D+1 12:00 之后才算缺卡；
- 定时器每小时 :05 + 惰性补算双保险；
- 幂等键固定，跑多少次只扣一次；
- 余额 0 时 `penalize` 返回 0，不写流水（已知问题，见 T33）。

代码：`index.js:66`。

### 6.3 申诉 `appeal`

```
校验 → approvals.create({
  module:'checkin', type:'late_night'|'late_wake',
  refId: dayKey + ':' + type,
  toOpenid: partner,
  payload: { dayKey, type, penalty, reason }
})
→ 对方同意 → onDecision.late_night/late_wake → refundIfApproved
→ hearts.apply(+penalty, reason='申诉通过退回', idemKey='appeal:<ticketId>')
```

代码：`index.js:293` / `:408`。

### 6.4 改规则 `proposeConfig`

```
规则页编辑 → 本地 validateConfig → checkin.proposeConfig(完整 config)
→ approvals.create({ type:'rules_change', payload:{ config }, refId:'rules:'+Date.now() })
→ 对方同意 → onDecision.rules_change → settings.save(coupleId,'checkin',config)
→ 只影响之后的打卡；已发爱心不回滚
```

代码：`index.js:335` / `:398`。

### 6.5 摘要 / 详情

- `summary`：只返回 4 个数字，给首页宫格。
- `detail`：返回今日状态、最近 7 天、本月统计、双侧日历、漏卡列表、完整 config。
- `history`：按月统计 + 流水，当前前端未调用。

## 九、前端页面结构

### 9.1 打卡页 `pages/m/checkin/index`

| data | 来源 | 说明 |
|---|---|---|
| `streak` | `detail.streak` | 连续全勤 |
| `items` | `rules.describeToday()` | 今日两项的按钮/提示 |
| `cells` | `buildCells(calendar)` | 日历 42 格 |
| `misses` | `detail.misses` | 漏卡卡片 |
| `monthText` / `monthReached` | `detail.month` | 本月进度 |
| `float` | `act.reward` | +N 动画 |

三个关键实现：

1. **服务器时间偏移**：`offset = serverNow - Date.now()`，每秒用 `Date.now()+offset` 重算；
2. **每秒重绘**：`setInterval`，`onHide`/`onUnload` 清掉；
3. **打卡后重拉整页**：不自己改状态，避免前后端算法不一致。

### 9.2 规则页 `pages/m/checkin/rules/index`

- `mode=view`：`buildSummary` 翻译成人话；
- `mode=edit`：时间/数字输入，联动档位边界；
- 提交前本地 `validateConfig`，服务端再校验一次；
- 提交成功 = 已发工单，不等于生效。

## 十一、怎么改（常见需求）

### A. 改默认窗口/分值

改 `shared/checkin-rules.js` 的 `DEFAULTS` → `node scripts/sync-rules.mjs` → 跑测试 → 部署云函数。
**但你们两个人用，直接在小程序规则页改 + 对方同意就行，不用发版。**

### B. 加一档奖励

1. `DEFAULTS.sleep.tiers` 插入一档（必须首尾相接）；
2. 规则页能改边界/分值，但**不能增删档位**；增档要改代码；
3. 更新 `validateConfig` 的「最多 8 档」；
4. 测试：新档位的边界。

### C. 加第三个打卡项（运动）

不要复制 `checkin` 目录。两个选择：

| 方案 | 做法 | 代价 |
|---|---|---|
| 同模块加 `type` | 改 `TYPES`/`LABELS`/`DEFAULTS`；日历两行变三行；校验器；页面 | 中，但共享窗口/结算逻辑 |
| 新模块 `sport` | 新建模块，复用规则模式 | 大，但边界干净 |

先问：它和早睡早起共享「一晚」的概念吗？不共享就做新模块。

### D. 加补签卡

1. 打卡模块加 `action: makeup`；
2. 校验：缺卡、未超过 N 天、有卡（商城）；
3. 写 `checkins`，`source:'makeup'`，`hearts:0`；
4. 不发爱心；如果发，必须带 `idemKey`；
5. 商城卖卡（`shop` 模块）。

### E. 加打卡提醒

依赖 `notify`（未实现）：
1. 21:30 扫描未打卡用户；
2. 频控每天 1 条；
3. `idemKey = remind:sleep:<day>:<openid>`；
4. 用户没授权 → 不发，不影响打卡。

## 十二、排查清单

| 现象 | 先查 |
|---|---|
| 点打卡「未开放」 | 云端时间、规则窗口、`windowState` |
| 打卡成功但没爱心 | 档位是否 0 分；`checkins.hearts` |
| 连续天数不对 | 打卡日是否跨 cutover；查询是否带 coupleId |
| 日历少一天 | 是否归到上个月（11-01 早上算 10-31） |
| 漏打没扣 | 定时器部署了吗；余额是否为 0；是否在 pairedAt 之前 |
| 扣两次 | `heart_logs` 里 `miss:<type>:<day>` 有几条 |
| 申诉没退分 | 工单 status；`applied.error`；`appeal:<ticket>` 流水 |
| 改规则没生效 | 对方同意了吗；`core_settings.patch` 更新了吗 |
| 规则页白屏 | 云函数是否旧版（config 结构）；页面有兜底但最好重新部署 |
